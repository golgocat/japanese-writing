# 要約と文字数

要約では、原文の意味を保ったうえで指定の長さへ収める。
字数だけが合っていても、留保や未決定事項を失った文章は合格にしない。

## 制約を分ける

| 指定 | 扱い |
| --- | --- |
| 100字以内 | 100字以下の厳密な上限 |
| 100字ちょうど | 100字との一致 |
| 約100字、100字程度 | 100字を目安にする。許容幅を勝手に必須条件にしない |
| 100〜120字 | 両端を含む範囲。媒体指定があればそれに従う |

「100字」とだけある場合は用途から判断する。
通常の要約なら目安として進められるが、提出欄などの上限がある場合は規約を確認する。
質問なしで合理的に決められる場合は、採用した計数方法を必要に応じて短く示す。

## 要約の順序

1. 読者と要約の目的を確認する。
2. 結論、重要な事実、条件、否定、留保、主体を固定する。
3. 重複、前置き、補助例、目的に不要な詳細から削る。
4. 指定の文字数で計数する。
5. 原文と照合し、判断や確信度が変わっていないか確認する。
6. 修正した場合は最終稿を計数し直す。

全文の要約か、指定論点だけの抜粋かを混同しない。
短くするために、原文にない因果関係や結論を作らない。
具体例や数値は、主張を支える根拠なら短くても残す。補助的な例は代表例や共通点へ圧縮できるが、例外や反証を消して一般化しない。
複数箇所から文を抜き出してつなぐ場合は、主語・述語と因果関係を再確認する。
「要約と感想」の依頼では両者を分ける。単なる要約へ自分の評価や提案を足さない。

## 保持する留保

```text
原文：試験導入では30人中24人の作業時間が短縮した。
全社で同じ効果が出るかは未確認で、費用も未確定のため、正式導入はまだ決めていない。

要約：試験では30人中24人の作業時間が短縮した。
全社での効果は未確認、費用は未確定で、正式導入は未決定。
```

上は意味保存の例であり、特定字数の合格例ではない。
「導入で作業時間が短縮。全社展開へ」では未確認と未決定が失われる。
省略で結論が変わる条件は、短い語へ変えても残す。

## 長さごとの組み立て

次は、原文に十分な情報がある場合の構成目安。必須の型や字数の埋め方ではない。

| 長さの目安 | 優先する内容 |
| --- | --- |
| 30〜50字 | 中心となる結論と、結論を変える留保・条件 |
| 100字前後 | 結論、主な根拠、重要な条件や未決定事項 |
| 200字前後 | 背景、主要な事実、判断、必要な次の行動 |
| 400字前後 | 複数の主要論点、その根拠と関係、判断、残る課題 |

原文が短いときは、字数を埋めるための背景・評価・将来予測を足さない。
複数の字数を求められたら、共通の意味メモから各版を作り、それぞれ実測する。
短い版で省略した情報を長い版に戻し、版ごとに結論・数値・確信度を変えない。
各版は単独で理解できるようにし、「上記のとおり」で他の版に依存させない。

## 文字数の単位

Unicodeのコードポイント、見た目に近い書記素クラスタ、UTF-16の単位、バイト数は異なる。
結合文字や絵文字では同じ文字列の計数結果が変わる。
JavaScriptの `.length` をすべての用途の文字数として扱わない。

汎用ヘルパーの既定は次のとおり。

- 単位：Unicodeコードポイント。
- 正規化：なし。入力原文を書き換えない。
- 改行：除外。
- 空白：含める。
- 計数対象：渡された本文。見出しや注記を自動で判別して除かない。

外部の提出規約や媒体カウンターがあれば、その規則を優先する。
既定値は日本語全般の普遍的な文字数定義ではない。

## ヘルパーの使用

`scripts/count_characters.mjs` に、計数したい本文だけを標準入力で渡す。
本文ファイルには、字数表示や説明用コードフェンスを混ぜない。

```sh
node scripts/count_characters.mjs --max 100 < draft.txt
node scripts/count_characters.mjs --exact 100 < draft.txt
node scripts/count_characters.mjs --target 100 < draft.txt
```

`--max` は上限以下、`--exact` は一致を判定する。
`--target` は目標との差を返し、許容幅なしの合否は返さない。
範囲指定では、実測値が下限以上かつ上限以下かを確認する。

計数規約を変える場合は明示する。

```sh
node scripts/count_characters.mjs --unit graphemes --max 100 < draft.txt
node scripts/count_characters.mjs --unit utf16 --max 100 < draft.txt
node scripts/count_characters.mjs --unit bytes --max 300 < draft.txt
node scripts/count_characters.mjs --normalization NFC --max 100 < draft.txt
node scripts/count_characters.mjs --line-breaks include --max 100 < draft.txt
node scripts/count_characters.mjs --exclude-spaces --max 100 < draft.txt
```

`bytes` はUTF-8のバイト数であり、字数とは呼び分ける。
入力はUTF-8。不正なバイト列は置換して数えずエラーにする。BOMは既定で1コードポイントとして残る。
NFCは計数用の正規化として使い、原文保存の依頼で黙って本文を変えない。
空白や改行の扱いが提出先と一致するか確認する。
書記素クラスタは利用ランタイムのUnicode実装に依存するため、厳密な再現では実行環境も記録する。

## 媒体固有の制約

Xなどは、URLや絵文字などに独自の計数規則を持つ。
汎用ヘルパーだけで投稿可能と保証しない。
公式の実装または実際の媒体カウンターで確認する。
未確認なら、汎用字数の確認と媒体への適合確認を分けて報告する。
特定の数値上限を、すべての投稿形式や将来仕様へ固定しない。

## 出力と限界

本文のみの依頼には、字数の説明を本文へ混ぜない。
必要なら本文と別に「コードポイント数、改行除外、空白込み」などの規約を示す。
ちょうど指定のために、意味のない句読点や形容詞を足して埋めない。
必要な意味と上限が両立しない場合は、不両立を短く伝える。
重要な条件を消した短文を完成扱いにしない。

## 一次資料

- [Unicode UAX #29](https://www.unicode.org/reports/tr29/)：書記素クラスタとコードポイントの違い、知覚上の文字の近似、データ量制限との違い。日本語作文や原稿用紙の規約を定める資料ではない。
- [X Counting Characters](https://docs.x.com/fundamentals/counting-characters)：重み付き計数、URL・絵文字の扱い、NFC、公式実装の案内。個別の投稿形式ではその時点の仕様を確認する。
