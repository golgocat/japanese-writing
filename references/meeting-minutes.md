# 議事録モード

議事録・打合せ記録を、用途と指定書式に合わせて整えるための参照。
一般的な構造候補と、本ユーザー案件の共有プロファイルを分けて扱う。
逐語録、発言者別、時系列などの明示指定は、下記の既定形式より優先する。

## 適用する場面

- 議事録、打合せ記録、MTGメモを清書・再構成する。
- 文字起こしやメモから、決定・宿題・未確定事項を整理する。
- 会議の成果を、参加者や関係者へ共有する文書を作る。

広告・販促や創作表現の技法は持ち込まない。
Japanese WritingのTarget qualityとWorkflowの原文照合を適用する。

## 原記録と指定書式

- 指定された粒度、順序、発言者の表示方法を先に確認する。
- 逐語録を勝手に要約し、発言者別記録を勝手にテーマ別へ変えない。
- 要旨型ならテーマごとに整理できるが、反対意見や条件付き合意は残す。
- 省略された主語・対象は、文脈から確実な場合だけ補う。
- 不明な氏名、所属、役職、担当、日付、数値は推測で埋めない。
- 人名は Keyterms・用語集・参加者一覧の表記を使う。そこになく漢字が不明な日本人名はカタカナ、外国人名はアルファベットで書き、漢字を推測せず都度利用者に確認する。音が似ているだけで登録名に寄せない。

引用が必要な箇所と、要約してよい箇所を分ける。
発言者の意見を、会議全体の結論へ変えない。

記録方式は、短さだけでなく何を残すかで区別する。

| 方式 | 残すもの |
| --- | --- |
| 逐語録・全文筆記 | 原発言の文言、発言順、指定された発言者や時刻 |
| 要点筆記 | 発言の趣旨を短くした記録。指定された発言順と応答関係 |
| 議事要旨 | 論点、経過、結果の概要。決定・異論・留保の区別 |

「要点筆記」は発言の圧縮を求める指定であり、テーマ別への並べ替えまで意味しない。
内容を清書できたことと、参加者や主催者がその内容を承認したことも区別する。

## 決定と未決定を区別する

| 状態 | 記録する内容 |
| --- | --- |
| 決定 | 合意・決裁された内容と適用条件 |
| 提案 | 出された案。採否が不明なら決定扱いにしない |
| 継続検討 | 引き続き検討する論点と確認事項 |
| 保留 | 判断を待つ事項と、記録にある保留理由 |
| 報告 | 共有された事実や進捗。意見と区別する |
| 対応・宿題 | 誰が何を行うか、確認された期限 |

```text
決定：移行テストを10月2日に実施する。
提案：本番移行を10月中旬に行う案が出た。日程は未決定。
保留：夜間対応費の扱い。追加見積もりを確認して判断する。
対応：田中さんが追加見積もりを取得する。期限は記録にない。
```

依頼の発言だけでは、相手の受諾や担当確定を意味しない。
「未定」と「記録にない」も区別する。
「来週」の基準日が分からない場合は、具体的な日付を作らない。

## 一般的な構造候補

要旨型の議事録なら、重要事項から詳細へ進む構造が使える。

1. 標題：プロジェクト名や議題で内容を特定する。
2. 内容要旨：決定、方針、持ち帰りを区別して短く示す。
3. 詳細：論点ごとに根拠、条件、異論、経緯を補う。
4. 対応事項：担当と期限を、記録にある範囲で示す。

要旨の項目数や字数を、会議の規模に関係なく固定しない。
短い会議に多段の見出しを追加する必要はない。

## 基本情報

用途と指定書式に応じて、次の情報を残す。

- 日時：判明している日付と時刻。開始・終了の不明部分を作らない。
- 場所：会議室、オンラインなど、記録にある情報。
- 出席者：確認できる氏名・所属・役職。序列を推測しない。
- 次回：確定、候補、未定を区別する。想定を確定予定として書かない。

不足項目は、必要なら「記録なし」とするか、指定に応じて省略する。
宿題の担当や期限が欠けている場合、欠落を見える形で残す。
項目を埋めること自体を目的にしない。

## 本ユーザー案件の共有プロファイル

次は既存案件の共有スタイルを引き継ぐプロファイルであり、一般読者への必須形式ではない。
現在の依頼で別の書式が明示されていれば、その指定を優先する。

1. 項目ごとのタイムスタンプは付けない。会議自体の日時は残す。
2. AI使用、ASR、文字起こし、自動生成などの出力メタや定型免責は本文に足さない。
3. em dashや類似のダッシュで文をつないだり、間を演出したりしない。
4. 各決定・論点・宿題は、1トピック1行の箇条書きにする。
5. 内容要旨・決定事項を先に置き、運営・設計などの補足は後に置く。
6. 日本語版を最終確定してから英語版を作る。日本語にない情報を足さない。
7. 共有する成果物は最終稿とし、作業メモや推敲説明を混ぜない。
8. 本リポジトリの品質基準を適用し、演出過多・翻訳調を避ける。

「1行」は編集上の一つの箇条書きを指し、表示幅による自然な折返しは妨げない。
出力メタを省くことは、重要な実データの不確実性を隠す意味ではない。
聞き取れない数値や発言者、未確認の合意は、該当箇所で事実として明示する。

## 共有フォルダ・履歴・下書きの境界

既存案件で承認された運用では、履歴を持ち越さない共有用コピーと最終稿を用意する。
ただし、この文章スキルを使うこと自体は、履歴の除去や下書きの削除を許可しない。
対象フォルダ・文書と操作が承認された場合だけ、指定範囲で実行する。
原記録や未承認の下書きを自動削除せず、外部共有・公開も別の実行権限に従う。
文章だけの清書依頼では、最終稿を作るところまで進める。

## 共有用の構造例

```text
標題
日時／場所／出席
内容要旨／決定事項
- 決定または方針を1トピック1行で記載。
補足（運営）
- 必要な論点だけ記載。
補足（設計・工程）
- 必要な論点だけ記載。
宿題
- 担当者、対応、確認された期限を記載。
次回会議
主な未確定（あれば）
```

関係のない見出しは省略できる。英語版も同じ順序・粒度で対訳する。
所見は必要な社内稿に限り、会議の事実と分ける。対外稿へ自動追加しない。

## 最終確認と参考

- 決定、提案、保留、報告、依頼を取り違えていないか。
- 不明な時刻、次回予定、担当、期限を作っていないか。
- 指定された原記録の粒度と共有プロファイルの適用範囲を守ったか。
- 重要な異論、条件、留保を消していないか。
