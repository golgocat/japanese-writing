# 用途別改訂の動作確認

対象：SAT-227。3名のCodexサブエージェント（gpt-6-astra、medium）による出力を親エージェントが確認した。
評価用の依頼とスキルを渡し、期待文言・採点条件は渡さなかった。結果は文言一致ではなく、意味・目的・指定制約で判定した。
これは人間による編集審査や、全モデル・全用途に対する品質保証ではない。

## 結果

- 初回改訂では[cases.json](cases.json)のうち36件を確認。最終出力では全件が記載の観点を満たした。
- 初回30件のうち、S01は許可者と実行者の曖昧さ、M08は無料条件の位置を改善し、別の評価担当で再実行した。
- 敬語の慣用例、初回連絡、昇進祝い、複数字数要約、承認者と公開者の区別、UTCの保持を6件追加した。
- 日本語文例の「費用未確定→未確認」、昇進だけからの部署異動の追加、旧見出しへの参照を修正した。
- 文字数ヘルパーの自動テストは8件成功。不正UTF-8の暗黙置換を修正し、回帰例を追加した。
- `quick_validate.py`と`git diff --check`を通過した。

## 実測した文字数

コードポイント、改行除外、空白・句読点込み、正規化なし。見出しと字数注記は対象外。

| ケース | 指定 | 最終本文の実測 |
| --- | --- | --- |
| S05 | 50字以内 | 45字 |
| S06 | 50字ちょうど | 50字 |
| S09（短） | 50字以内 | 50字 |
| S09（中） | 100字以内 | 87字 |
| S09（長） | 200字以内 | 128字 |

S09は3版とも全社効果未確認・費用未確定・正式導入未決定を保持した。
短い版で省略した根拠や周辺情報を長い版へ戻し、原文にない結論は追加していない。
T02・T03の原文行は、出力の英文行との完全一致と対応行数を機械確認した。

## 再確認の方法

1. 用途を変えた新しい依頼でも、スキルを読んだ評価担当に実際の回答を作らせる。
2. 原文との追加・脱落・条件・否定・責任の変化を人手で照合する。辞書や文字列一致だけで採点しない。
3. 字数制約がある本文は `scripts/count_characters.mjs` で実測する。
4. スクリプト変更時は `node --test scripts/count_characters.test.mjs` を実行する。

## Exa再開後の追加確認

HTTP 402の解消後、Exaで4分野・15検索を実施した。73件の検索結果を71のURLへ整理し、関連する20資料の必要箇所を本文で確認した。
URLは完全一致の重複と追跡パラメータ`_fsi`の差を除外して集計した。
新たな出典に基づく編集基準を反映し、次の12ケースを追加した。別分野を担当した評価者に採点条件を渡さず生成させ、親が実出力を照合した。

| ケース | 確認した点 | 結果 |
| --- | --- | --- |
| P10 | 相手の承諾が必要な依頼 | 担当を決定済みにせず、依頼の形を保持 |
| P11 | 迎えた側からのお礼 | 来訪へのお礼とし、招かれた側へ逆転せず |
| P12 | 配送遅延の経過報告 | 商品の所在確認、原因・到着日未確定を区別 |
| P13 | 同僚の母に宛てる弔意 | 宛先の父が亡くなった文にせず、中立表現で対応 |
| S11 | 動作を体言止めにする場合 | 進行中・完成・検討中を保持 |
| S12 | 一つの項目だけに掛かる条件 | 契約締結の承認条件を見積取得へ広げず |
| S13 | 要点筆記 | 発言順と提案・希望の状態を保持 |
| S14 | 50字以内の要約 | 43字。失敗例と全件対応未確認を保持 |
| T10 | 留保を残すやさしい日本語 | 5営業日程度と、追加確認時の遅延可能性を保持 |
| T11 | 不明な年度の起算日 | 会社の2026年度を保持し、期間を補作せず |
| T12 | 順序依存の翻訳変数 | `%s`を2個保持し、申請・承認者の順序を維持 |
| T13 | 読み付き版とルビなし版 | 読みを除いた本文が原文と一致 |

初回36件と追加12件の計48ケースを確認した。初回36件を追加改訂後に全件再実行したという意味ではない。
S14の字数、T12の変数数、T13の読みを除いた本文も機械確認した。
文字数スクリプト自体の追加変更はなく、先に完了した8件の自動テスト結果を引き継いだ。
最終レビューでは、平易化の文例から「予定より長い」という比較が消えないよう、原文と改稿の双方に比較基準を明示した。
